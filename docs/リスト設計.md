# リスト設計.md — SharePointリストの構成と構築手順

版: v0.1 / 最終更新: 2026-08-12

要件は `docs/要件.md`、環境の仕様は `docs/環境台帳.md` を参照。
定義の実体は `src/lists_definition.json`、書式設定は `src/list_formatting.json`。

---

## 1. 構成

```
手配起票（親）   1行 = 1起票 = 1部材群 = 1納地
 └ 手配タスク    1行 = 手配方法ごとの作業単位
    └ 手配明細   1行 = 部材1点

許可バージョン   取り込みを許可する版数
起票受付         JSONの投入口（ドキュメントライブラリ）
```

---

## 2. 親子をどう繋ぐか

### 2.1 Lookup型ではなくテキストキーを使う

**起票IDとタスクID（UUID）を、そのまま連結の鍵とする。**

| | Lookup型 | テキストキー |
|---|---|---|
| 作成時 | 相手リストのGUIDが必要。作る順序に依存する | 依存なし |
| フローからの書き込み | 親の**数値ID**を取得して渡す必要がある | 値をそのまま入れるだけ |
| 起票ツールとの整合 | IDの変換が挟まる | **既に持っているUUIDをそのまま使える** |
| 画面での行き来 | 標準でリンクになる | リンク列を自前で用意する |

**繋ぎ替えや再取り込みに強く、フローも単純になる**ため、テキストキーを採る。
画面での行き来は §5 のリンク列で補う。

### 2.2 内部名を英字で固定する

**必ず `CreateFieldAsXml` で列を作ること。**

画面から手で作ると、内部名が `_x62c5__x5f53__x8005_` のような文字列になる。
フローやREST APIからは内部名で参照するため、日本語のままだと可読性が壊滅する。

```xml
<Field Type='Text' DisplayName='起票ID' Name='TicketId' StaticName='TicketId' ... />
        表示は日本語 ──┘              英字の内部名 ──┘
```

### 3.2 手配タスク

| 表示名 | 内部名 | 型 | 備考 |

| タスク名 | Title | 1行テキスト | 「起票の名前 / 手配方法」 |
| タスクID | TaskId | 1行テキスト | **必須・一意・索引** |

| 手配主担当 | MainAssignee | ユーザー | 索引 |
| 手配副担当 | SubAssignees | ユーザー（複数） | |

| 必要作業日 | RequiredDates | 複数行テキスト | 全段階分をJSONで保持 |
| 明細数 | DetailCount | 数値 | |
| 合計数量 | TotalQuantity | 数値 | |
| 内訳 | DetailDigest | 複数行テキスト | 「品名A×45 / 品名C×10 ほか27件」 |
| 明細を見る | DetailLink | ハイパーリンク | §5 |
| 完了 | IsCompleted | はい/いいえ | |
| 完了日時 | CompletedAt | 日付と時刻 | |
| 自動クローズ | AutoClosed | はい/いいえ | 検収の2か月クローズ |
| 統合先タスクID | MergedInto | 1行テキスト | 融合で消える側に入れる |
| 最後の通知 | LastCardLink | ハイパーリンク | カード応答の `messageLink` |
| 削除 | IsDeleted | はい/いいえ | |

#### 必要作業日を2つに分ける理由

段階ごとのリードタイムは手配方法によって数も種類も変わる。
**列を段階の数だけ用意すると、手配方法が増えるたびに列が増える。**

そこで、

- **`RequiredDates`** に全段階分をJSONで保持する（表示と参照用）
- **`NextDueDate`** に最も早い未達の日付だけを入れる（**索引・絞り込み・並べ替え・遅延判定用**）

日付での絞り込みには索引付きの日付列が要るため、この分離が必要になる。
`NextDueDate` はステータスが進むたびにフローが更新する。

### 3.5 起票受付（ドキュメントライブラリ）

```
起票受付/
├─ （直下）      … 未処理
├─ 取込済/
├─ 重複スキップ/

```

**取り込まなかった場合も必ず移動させる。** 直下に残るものが未処理、という状態を保つ。

## 4. ビュー

### 4.1 手配タスク

| ビュー名 | 絞り込み | 並べ替え |
|---|---|---|
| **自分の担当** | 手配主担当 = [自分] または 手配副担当 に自分を含む、完了 = いいえ | 次の必要作業日 昇順 |
| **遅延** | 次の必要作業日 < [今日]、完了 = いいえ | 次の必要作業日 昇順 |
| **今週** | 次の必要作業日 <= [今日]+7、完了 = いいえ | 次の必要作業日 昇順 |
| すべて | 削除 = いいえ | 次の必要作業日 昇順 |
| 完了済み | 完了 = はい | 完了日時 降順 |

**既定のビューは「自分の担当」にする。** 開いた瞬間に自分の仕事だけが見える状態にするため。

### 4.2 手配起票

| ビュー名 | 絞り込み |
|---|---|
| 進行中 | 状態 = 進行中、削除 = いいえ |
| すべて | 削除 = いいえ |

### 4.3 手配明細

**ナビゲーションに表示しない。** 行数が膨らむため、直接開く運用にしない。

| ビュー名 | 絞り込み |
|---|---|
| すべて | 削除 = いいえ |

タスクからの絞り込みリンク（§5）で開くことを前提とする。

## 5. リンク列

明細リストは別リストのため、タスクから中身が見えない。
**絞り込み済みのビューへ飛ぶリンクを、行ごとに持たせる。**

```
（サイトのURL）/Lists/手配明細/AllItems.aspx?FilterField1=TaskId&FilterValue1={タスクID}
```

- 取り込みフローが、行を作るときに `DetailLink` へ書き込む
- 親からタスクへ飛ぶ `TaskLink` も同じ仕組み（`FilterField1=TicketId`）
- 書式設定で「開く」ボタンの見た目にする（`list_formatting.json` の `共通_リンク`）

**セルにカードを開く書式設定**も存在するが、この環境で動くかは未検証。
動けば追加する。動かなくてもリンク列だけで実用になる。

## 6. 権限

**物理削除を禁止し、論理削除にする**（要件.md §11）。

```
1. アクセス許可レベルの一覧を開く
   （サイトのURL）/_layouts/15/role.aspx
2. 「投稿」をコピーし、「アイテムの削除」を外した新しいレベルを作る
3. 各リストの設定 →「このリストに対する権限」→ 継承を停止
4. メンバーに、新しいアクセス許可レベルを割り当てる
```

**サイト全体には適用しない。** ドキュメントライブラリでファイル名の変更ができなくなる。

## 7. 構築手順

### 7.1 リストと列を一括で作る

**`SharePoint に HTTP 要求を送信します` は標準で使える**（環境台帳 §C-2）。
以下のフローを1本だけ作り、実行すれば全リストが生成される。

**フロー名**: `管理_リストを構築する`（手動実行）

| # | アクション | 設定 |
|---|---|---|
| 1 | 手動でフローをトリガーします | — |
| 2 | 変数を初期化する（配列 `lists`） | `src/lists_definition.json` の `lists` をそのまま貼る |
| 3 | それぞれに適用する（`lists`） | 以下4〜6を含む |
| 4 | └ SharePoint に HTTP 要求を送信します | リスト作成（§7.2） |
| 5 | └ それぞれに適用する（`items()?['fields']`） | |
| 6 | └ └ SharePoint に HTTP 要求を送信します | 列作成（§7.3） |

**同時実行を1にする**こと（設定 → 同時実行制御）。列の作成順序が保たれる。

### 7.2 リストを作る

```
方法: POST
URI : _api/web/lists
ヘッダー:
  Accept: application/json;odata=verbose
  Content-Type: application/json;odata=verbose
本文:
{
  "__metadata": { "type": "SP.List" },
  "BaseTemplate": <template>,
  "Title": "<title>",
  "Description": "<description>",
  "ContentTypesEnabled": false
}
```

### 7.3 列を作る

```
方法: POST
URI : _api/web/lists/getbytitle('<title>')/fields/createfieldasxml
本文:
{
  "parameters": {
    "__metadata": { "type": "SP.XmlSchemaFieldCreationInformation" },
    "SchemaXml": "<Field ... />",
    "Options": 12
  }
}
```

`Options: 12` は「既定のビューに追加」と「すべてのコンテンツタイプに追加」の合計。

### 7.4 一意制約を設定する

**一意制約は列の作成と同時には効かない場合がある。** 作成後に画面から設定する。

```
リストの設定 → 対象の列 → 「固有の値を適用する」を [はい] → OK
  → 「この列にインデックスを付けますか？」と出たら OK
```

対象: 手配起票 の `起票ID` / 手配タスク の `タスクID` / 手配明細 の `明細ID`

### 7.5 Title列の表示名を変える

```
方法: MERGE（またはPATCH）
URI : _api/web/lists/getbytitle('<title>')/fields/getbytitle('Title')
ヘッダーに IF-MATCH: * を追加
本文: { "__metadata": { "type": "SP.Field" }, "Title": "<titleDisplayName>" }
```

### 7.6 書式設定を貼る

`src/list_formatting.json` から該当の項目をコピーし、
**列見出し → 列の設定 → この列の書式設定** に貼り付ける。

`$use` `$desc` `$comment` は説明用なので、貼る前に取り除く。

### 7.7 ビューを作る

§4 の表に従って画面から作成する。

### 7.8 権限を設定する

§6 の手順。**一度きりの作業**。

### 7.9 許可バージョンを登録する

配布した起票ツールの版数を1行追加する。

## 8. 索引の上限に注意

**1つのリストに作れる索引の数には上限がある**（20程度）。

現在の索引: 起票ID / タスクID / 明細ID / 手配主担当 / 手配方法 / ステータス / 次の必要作業日 / 状態

上限には遠いが、**列を増やすたびに索引を付けない**こと。
絞り込みと並べ替えに実際に使う列だけに付ける。

## 9. 未確認事項

1. **ユーザー型の列で複数値を許可できるか**（手配副担当）
   - 不可の場合、副担当をメールアドレスの複数行テキストで持ち、通知フロー側で分解する
2. `CreateFieldAsXml` で `EnforceUniqueValues` が一度に効くか
   - 効かなければ §7.4 のとおり画面から設定する
3. セルにカードを開く書式設定が動くか（§5）
4. 絞り込みリンクのURL形式が、この環境のビューで有効か

いずれも**設計の根幹には影響しない**。代替手段を用意済み。

## 10. 次にやること

リストが構築できたら、**取り込みフロー**を作る。

```
起票受付ライブラリ → 取り込み → 手配起票 / 手配タスク / 手配明細
```

設計は別途。フローは画面で組む必要があるため、
**アクションと設定値の表**を用意する（要件.md の想定どおり）。
