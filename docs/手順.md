# 0. 再利用可能な判定手法

## 0-1. プレミアムコネクタの判定

一覧の見た目だけでは可否が判断できない。以下で確定させる。

```
1. 非プレミアムのトリガー（例: スケジュール済みクラウドフローの Recurrence）で
   フローを作成する
2. 対象のアクション／トリガーを追加する（パラメータは未入力でよい）
3. フローチェッカー（聴診器のアイコン）を開く
4. 「警告(0)」であれば、そのアクションは標準ライセンスで使用可能
```

**「エラー」は必須パラメータ未入力によるもので、可否とは無関係。**

## 0-2. 到達しにくい設定画面

| 目的 | 到達方法 |
|---|---|
| アクセス許可レベルの一覧 | `（サイトのURL）/_layouts/15/role.aspx` へ直接アクセス |
| サイトの権限 | `（サイトのURL）/_layouts/15/user.aspx` |

サイト設定のトップに「ユーザーと権限」が表示されない場合がある（Teams連携サイトのため）。

## 0-3. よくある詰まりどころ

| 症状 | 原因と対処 |
|---|---|
| 「検索と一致する値がありません」（サイトアドレス欄） | ライブラリまでのフルパスを入れている。**サイトのルートまで**にする |
| 「使用可能なフローはありません」 | **ファイルを選択していない**。選択してからメニューを開く |
| 「この列にインデックスを付けますか？」 | 一意制約の設定時に出る正常な確認。**OKで進む** |

# 1. 第1サイクルの手順（実施済み・参照用）

## 1-A. 往路の成立

1. 会社PCのブラウザで GitHub のリポジトリを開く
2. `Code` → `Download ZIP`
3. ZIPを展開する（展開先を記録）
4. Coworkに `PROJECT.md` を読ませ、3行で要約させる

## 1-B. SharePointリスト

1. サイト → `新規` → `リスト` でテストリストを作成
2. 以下の型の列を追加できるか確認する
   - ユーザーまたはグループ（Person型）／日付と時刻／選択肢／参照（Lookup）／数値
   - **【撮影】列の型を選ぶダイアログの全選択肢**
3. Person型の列に自分を設定してみる

## 1-C. Power Automate のコネクタ

§0-1 の手法で、以下を判定する。

- トリガー: SharePoint / Box / Teams / Forms / スケジュール / HTTP要求の受信時
- アクション: `SharePoint に HTTP 要求を送信します` / Box のコンテンツ取得 /
  Teams のカード投稿・メンショントークン

# 2. 第2サイクルの手順（実施済み・参照用）

## 2-A. ローカルHTML（Box Drive経由）

Box Drive の同期フォルダに `test_a.html` と `test_b.html` を作成し、
エクスプローラーからダブルクリックで開く。

**検証内容**

- JavaScriptが動作するか
- `mailto:` でOutlookが起動するか（件名の日本語・本文の改行・記号）
- 相対リンクでもう一方のHTMLへ遷移できるか
- URLパラメータ（日本語を含む）が渡るか

**テスト用HTMLは `src/` に置く**（`test_a.html` / `test_b.html`）。

## 2-B. 一意制約

```
リストの設定 → 列（1行テキスト）→ 「列の追加設定」
 → 「固有の値を適用する」を [はい] → OK
 → 「インデックスを付けますか？」が出たら OK
```

## 2-C. 手動フロー実行

1. ドキュメントライブラリを作成する
2. Power Automate → インスタント クラウド フロー
   → トリガー **「選択したファイルの場合」（SharePoint）**
   - OneDrive for Business の同名トリガーと間違えないこと
3. サイトアドレス（**ルートまで**）とライブラリ名を指定
4. §0-1 でプレミアム判定

## 2-D. Microsoft Forms

1. フォームを作成し、テキスト形式の質問を3つ追加
2. 編集画面の […] → **「事前入力済み URL の取得」**
3. 値を入れてリンクを生成する
   - **必ず正式形のURL**（`/Pages/ResponsePage.aspx?id=...`）を使う
   - 短縮形（`/r/XXXXXX`）は転送時にパラメータが消える

## 2-E. アダプティブカード

1. インスタント クラウド フロー →
   **「アダプティブ カードを投稿して応答を待機する」**
2. 投稿者: フロー ボット／投稿先: フロー ボットとチャットをする
3. **メッセージ欄に、カードのJSONをそのまま貼り付ける**
   （テキストを入れると入力欄が出ない）
   - テスト用JSONは `src/test_card.json`
4. テスト実行 → Teamsに届いたカードで値を入力して送信
5. 実行履歴 → アクションの **出力** を確認

# 3. 第3サイクルの手順（未実施）

## 3-1. カードの応答者を識別できるか【最優先】

**所要時間: 数分。** 既存の実行履歴を見るだけで済む。

```
Power Automate → 対象のフロー → 28日間の実行履歴 → 該当の実行をクリック
 → 「アダプティブ カードを投稿して応答を待機する」のブロックをクリック
 → 「出力」の body を、上下にスクロールして全項目を見る
```

**【撮影】** body の全項目（スクロールして複数枚に分けてよい）

**確認したいこと**

既知の項目（`data.status` `data.newdate` `data.comment` `messageLink`）**以外に**、
応答者を識別できる情報（メールアドレス、ユーザー名、ID など）が含まれるか。

**「未加工の出力を表示する」** を押すと全体をまとめて見られる。

**判定の意味**

| 結果 | 影響 |
|---|---|
| 応答者情報がある | `要件.md` §5.6 の応答者検証が実装できる |
| 無い | チャネル投稿したカードの操作を担当者に限定できない。カードを個人チャットへ切り替えるか、検証を諦めるかを選ぶ |

## 3-2. スレッド返信でトリガーが発火するか

**前提**: 3-1 が済んでから。優先度は中。

1. テスト用のチャネルに、フローボットから何か投稿する
2. Power Automate で
   **「チャネルに新しいメッセージが追加されたとき」**（Teams・標準）のフローを作る
   - 対象のチームとチャネルを指定
   - アクションは何でもよい（変数の初期化など）
   - 保存して有効化する
3. **1で投稿したメッセージのスレッドに返信する**
4. フローが発火したか、実行履歴で確認する

**【撮影】** 実行履歴（発火していれば実行が1件増えている）

**確認したいこと**

- 新規投稿だけでなく、**スレッドへの返信**でも発火するか
- 発火した場合、出力に**スレッドの識別子**が含まれるか
  （`messageLink` と突き合わせられるか）

**判定の意味**: `要件.md` §5.7 のテキスト返信によるステータス更新の可否。
発火しなければこの機能は諦め、カード操作のみとする。

## 3-3. Box Drive へのファイル配置でトリガーが発火するか

**優先度: 低。** 投入口はSharePointライブラリとしたため、設計には影響しない。

1. Boxコネクタの「ファイルが作成されたとき」でフローを作る
2. Box Drive（同期フォルダ）にファイルを置く
3. 発火するか確認する（同期の完了を待つ必要がある）

## 3-4. 新しい Outlook での mailto

**優先度: 低。**

既定のメールアプリを「新しい Outlook」に切り替え、
`src/test_a.html` の mailto リンクを試す。

**確認したいこと**: 件名の日本語・本文の改行・記号が classic と同じか。

**判定の意味**: ノウハウ集 §0-1 で「classic を既定にしてください」と
案内する必要があるかどうか。
