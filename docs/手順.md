
# 優先度A：往路の成立（最優先）

**ここが死ぬと以降のすべてが止まる。** 必ず最初に確認する。

## A-1. GitHubへの到達

会社PCのブラウザで以下を開く。

```
https://github.com/at-gst22/task-ledger2026
```

- 期待: リポジトリのページが表示される
- 【撮影】表示された場合も、遮断された場合も撮影する

**判定**
- 表示された → OK
- プロキシ/フィルタで遮断 → **往路が成立しない。代替手段の検討が必要**

## A-2. ZIPの取得

リポジトリのトップで `Code` ボタン → `Download ZIP` を押す。

- 期待: ZIPファイルがダウンロードされる
- 【撮影】ブロックされた場合はその画面

## A-3. 展開と配置

ダウンロードしたZIPを展開する。

- 展開先はどこか（ローカルのDownloads / Box配下 / その他）を記録する
- 期待: PROJECT.md, CLAUDE.md, docs/ が展開される

**判定**
- 展開できた → 展開先パスを環境台帳に記録（**社内固有パスは書かず、種別のみ**。例:「Box同期フォルダ配下」）
- 展開できない → 制限内容を記録

## A-4. Coworkからの参照

Coworkに、展開したフォルダ内の `PROJECT.md` を読ませる。

```
（Coworkへの指示例）
展開したフォルダの PROJECT.md を読んで、内容を3行で要約してください。
```

- 期待: 内容を要約できる
- 【撮影】Coworkの応答画面

**判定**: Coworkがローカルファイルを読めるかの確認。読めない場合、以降の運用方法を再検討する必要がある。

# 優先度B：台帳の置き場所を決める（本命）

**要件.md §2 の3層構造（起票 → 部材群 → 明細 → 手配タスク）を実現できるかを確認する。**

## B-1. SharePointリストの作成権限

SharePointサイトを開き、新しいリストを作成できるか試す。

- 手順: サイト → `新規` → `リスト`
- **テスト用の名前で作成すること**（例: `test_ledger_20260812`）
- 期待: リストが作成できる
- 【撮影】作成メニューの画面、および作成後のリスト

**判定**
- 作成できた → OK。**リスト名を控えておく（後の手順で使う）**
- `新規` が出ない / 権限エラー → 権限不足。管理者への申請が必要

## B-2. 列の型を確認する

B-1で作ったリストに、以下の型の列を追加できるか確認する。

| 追加する列 | 型 | 用途 |
|---|---|---|
| `担当者` | **ユーザーまたはグループ（Person型）** | Teamsメンションに必須 |
| `現地使用日` | 日付と時刻 | 逆算の起点 |
| `ステータス` | 選択肢 | 9段階の管理 |
| `親ID` | **参照（Lookup）** | 親子構造に必須 |
| `数量` | 数値 | 明細 |

- 【撮影】**列の型を選ぶダイアログの全選択肢一覧**（これは自宅では絶対に分からない情報）

**判定**
- **Person型が使えるか** ← 最重要。使えない場合、担当者マスタを別に持つ設計に変わる
- **参照（Lookup）型が使えるか** ← 親子構造に必須。使えない場合、IDを手で持つ設計に変わる

## B-3. Person型からメールアドレスが取れるか

B-2で `担当者` 列（Person型）を作れた場合のみ実施。

- リストに1行追加し、`担当者` に**自分自身**を設定する
- 【撮影】設定後の行の表示

**判定**: 人が選択でき、内部に識別子が保持されているように見えるか。厳密な確認はB-6で行う。

## B-4. カスタム権限レベルの作成可否

サイトの設定から、権限レベルの一覧を開けるか確認する。

- 手順: サイト設定 → サイトの権限 → （詳細設定）→ 権限レベル
- 期待: 権限レベルの一覧が表示され、`Contribute` のコピーが作れる
- **注**: サイト設定のトップに「ユーザーと権限」セクションが表示されない場合がある
  （Teams連携サイトのため）。その場合はブラウザのアドレスバーに
  サイトのURL + `/_layouts/15/role.aspx` を直接入力して到達すること
- 【撮影】権限レベル一覧の画面

**判定**
- 一覧が開ける → 論理削除＋物理削除禁止の設計が可能
- 開けない / メニューが無い → **物理削除の禁止は権限では実現できない。ツール側の制御と運用ルールのみで対応する**

## B-5. Power Automate のコネクタ権限

### プレミアム判定の方法

一覧の表示だけでは可否が判断できない。以下の手順で確定させる。

1. 非プレミアムのトリガー（例: スケジュール済みクラウドフローの Recurrence）でフローを作成する
2. 対象のアクションを追加する（パラメータは未入力でよい）
3. フローチェッカーを開き「警告」タブを確認する
4. 「警告(0)」であれば、そのアクションは標準ライセンスで使用可能

※「エラー」は必須パラメータ未入力によるもので、可否とは無関係

Power Automate を開き、新しいフローの作成画面でコネクタを検索する。

以下のコネクタが**プレミアム表示になっているか**を確認する。

| コネクタ | 確認内容 |
|---|---|
| SharePoint | プレミアムか、標準か |
| Excel Online (Business) | 同上 |
| Box | **存在するか。プレミアムか** |
| Office 365 Outlook | 同上 |
| Microsoft Teams | 同上 |

- 【撮影】コネクタ検索結果の一覧（プレミアムのマークが見える状態で）

**判定**
- Boxコネクタがプレミアムで使用不可 → **Box上のファイルをPower Automateから触れない**
- 標準コネクタのみ使える → SharePoint中心の構成で組む

### 追加確認①: SharePointへのHTTP要求送信アクション

Power Automate の SharePoint コネクタのアクション一覧に
「**SharePoint に HTTP 要求を送信します**」があるか確認する。プレミアム表示かどうかも確認する。

- 【撮影】アクション一覧（プレミアムのマークが見える状態で）

**判定**: 本番リストの構築を自動化できるかの分岐点。

### 追加確認②: HTTP要求の受信時トリガー

「**インスタント クラウド フロー**」のトリガー一覧に
「**HTTP 要求の受信時**」があるか確認する。プレミアム表示かどうかも確認する。

- 【撮影】トリガー一覧（プレミアムのマークが見える状態で）

**判定**: 起票UIから台帳へ自動書き込みできるかの分岐点。

## B-6. Box上のExcelにトリガーを張れるか

Power Automate で新しいフローを作り、以下を試す。

1. トリガーとして `Excel Online (Business)` のトリガーを検索する
2. **どのようなトリガーが存在するか**を確認する（「行が変更されたとき」があるか）
3. ファイルの場所として **Boxを選べるか**を確認する

- 【撮影】トリガー一覧、およびファイル選択のダイアログ

**判定**
- Box上のExcelを選べない → **台帳はSharePointリストに確定**
- 選べる → 選択肢として残る（ただし要件.md §2 の3層構造にはSharePointが有利）

## B-7. SharePointリストのトリガー

Power Automate で、`SharePoint` のトリガーを確認する。

- 期待: 「項目が作成されたとき」「項目が作成または変更されたとき」がある
- B-1で作ったテストリストを選択できるか確認する
- 【撮影】トリガー一覧とリスト選択のダイアログ

**判定**: これが使えれば、通知の自動化の土台が成立する。

# 優先度C：Teams連携

**要件.md §8 の通知5種と、双方向の書き戻しが可能かを確認する。**

## C-1. Teamsへの投稿

Power Automate で、`Microsoft Teams` のアクションを検索する。

以下があるか確認する。

- 「チャットまたはチャネルでメッセージを投稿する」
- 「アダプティブカードを投稿して応答を待機する」 ← **双方向に必須**
- 「選択肢のあるアダプティブカードを投稿して応答を待機する」

- 【撮影】アクション一覧

**判定**
- 「応答を待機する」系が無い → **Teamsからの書き戻しは別の方法を検討する必要がある**

## C-2. メンションの取得

Teams のアクションに `@mention トークンを取得する` があるか確認する。

- 【撮影】検索結果

**判定**: これが無いと、本物のメンション（通知が飛ぶ形）を自動投稿できない。

## C-3. 実際に投稿してみる

**テスト用のチャネル、または自分だけのチャットに対して行うこと。業務チャネルには投稿しない。**

簡単なフローを作り、Teamsへメッセージを1件投稿する。

- 本文に自分へのメンションを含める
- 【撮影】Teams側に届いたメッセージ（**メンションが青くリンクになっているか、灰色の平文かが分かるように**）

**判定**
- 青いリンクで通知が飛ぶ → OK
- 灰色の平文 → メンションの実装方法を再検討する

## C-4. アダプティブカードの応答

C-1で「応答を待機する」アクションがあった場合のみ実施。

- カードに**選択肢と、自由入力欄**の両方を置けるか確認する
- 【撮影】カードの編集画面

**判定**: 要件.md §8 では Yes/No だけでなく値の入力も必要なため、入力欄が置けるかが要点。

## D-5. ブラウザでのHTML実行

起票UIは単一HTMLとして作る予定のため、以下を確認する。

- ローカルに置いたHTMLファイルをブラウザで開けるか
- JavaScriptが動作するか（社内ポリシーで制限されていないか）
- 【撮影】制限された場合のエラー画面

**簡易テスト**: 以下の内容で `test.html` を作り、ブラウザで開く。

```html
<!DOCTYPE html>
<html><body>
<h1 id="t">読み込み前</h1>
<textarea id="a" rows="5" cols="40" placeholder="ここにExcelから貼り付け"></textarea>
<div id="r"></div>
<script>
document.getElementById('t').textContent = 'JavaScript動作OK';
document.getElementById('a').addEventListener('paste', function(e){
  setTimeout(function(){
    var v = document.getElementById('a').value;
    var rows = v.split('\n').filter(function(s){return s.length>0;});
    var cols = rows.length > 0 ? rows[0].split('\t').length : 0;
    document.getElementById('r').textContent =
      '取得: ' + rows.length + '行 × ' + cols + '列';
  }, 0);
});
</script>
</body></html>
```

**追加テスト**: Excelから適当な範囲（ダミーの数値でよい）をコピーし、テキストエリアに貼り付ける。

- 期待: 「取得: N行 × M列」と表示される
- 【撮影】貼り付け後の画面

**判定**: これが動けば、**起票UIのExcel貼り付け機能は実現可能**と確定する。要件.md §3.3 の前提が成立する。
