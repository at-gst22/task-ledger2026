# implementation-history — 実装依頼の履歴

**完了した実装依頼を保管する場所。**

現在の依頼は `docs/implementation-request.md` にある。
開発フロー全体は `docs/AI運用.md` §7、作業ルールは `CLAUDE.md` §6 を参照。

---

## 1. 命名

```
vNN_<短い件名>.md
```

- **連番は `v00` から。** ゼロ埋め2桁
- 件名は日本語でよい。**短く、あとから探せる語**にする
- 例: `v00_取り込みフローの雛形.md`

**空き番号を作らないこと。** 依頼が取り下げになった場合も、
その旨を記した本文とともに番号を残す。

---

## 2. 履歴化の手順

```
1. Codexの実装が完了し、ローカル Claude Code のレビューが通る
2. docs/implementation-request.md の内容に、実施結果（§10）を追記する
3. docs/implementation-history/vNN_<件名>.md として保存する
4. docs/implementation-request.md をテンプレートへ戻す
5. docs/進捗.md を更新する
6. 許可を得て commit / push
```

---

## 3. 完了済み履歴は変更しない

**原則として、一度履歴化したファイルは変更しない。**

追加や修正が必要になった場合は、**新しい実装依頼として扱う。**

```
悪い: v00 を書き換えて、あとから決めたことを足す
良い: v01 を新しく作り、「v00 の続き」と明記する
```

**理由**：履歴を書き換えると、
「そのとき何を決めて何を決めなかったか」が追えなくなる。
このプロジェクトは仕様が何度も変わっており、
**変わった経緯そのものが判断材料になる。**

### 例外

以下は変更してよい。

- 誤字の修正
- 参照している節番号が、他の文書の改訂でずれた場合の修正

**いずれの場合も、内容の意味を変えないこと。**

---

## 4. 実施結果に書くこと

履歴化する際、依頼の末尾に以下を追記する。

```
## 10. 実施結果

実施日: YYYY-MM-DD

### 変更したファイル

| ファイル | 内容 |
|---|---|

### 確認したこと

- 

### 依頼から変わった点

<実装の過程で変えたことがあれば、理由とともに>

### 積み残し

<この依頼では対応しなかったこと。次の依頼へ送るもの>

### 気づいたこと

<実装しなかったが、報告として残すこと>
```

**「積み残し」と「気づいたこと」を空欄で済ませないこと。**
無ければ「なし」と書く。**書き忘れと区別できなくなるため。**

## 5. 今回の開発体制の移行について

**開発体制の移行作業そのものは、履歴化していない。**

実装依頼ではなく、文書の整備であるため。
新体制で処理する**最初のアプリ実装依頼が `v00`** となる。
