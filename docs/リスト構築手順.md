# リスト構築手順.md — SharePointリストを作る

版: v0.1 / 最終更新: 2026-08-12

設計は `docs/リスト設計.md`、定義は `src/lists_definition.json`、
書式設定は `src/list_formatting.json` を参照。

---

## 進め方

```
第0段階  仕組みの確認     … 最小の1リストで試す。10分
第1段階  一括構築         … フロー1本で全リストを作る。30分
第2段階  仕上げ           … 一意制約・表示名・書式・ビュー・権限。30分
```

**第0段階を必ず先にやること。** ここで内部名が英字になることを確かめてから進む。

---

# 第0段階：仕組みの確認

## 0-1. テスト用のフローを作る

```
Power Automate → 作成 → インスタント クラウド フロー
  名前: test_listbuild
  トリガー: 手動でフローをトリガーします
```

## 0-2. リストを1つ作る

`+ 新しいステップ` → 検索 `SharePoint に HTTP 要求`

| 項目 | 値 |
|---|---|
| サイトのアドレス | 対象のサイトを選ぶ |
| 方法 | `POST` |
| URI | `_api/web/lists` |
| ヘッダー | 下記2行 |
| 本文 | 下記 |

**ヘッダー**（キーと値を2組）

```
Accept        : application/json;odata=verbose
Content-Type  : application/json;odata=verbose
```

**本文**

```json
{
  "__metadata": { "type": "SP.List" },
  "BaseTemplate": 100,
  "Title": "zz_test_build",
  "Description": "構築テスト用。あとで消す",
  "ContentTypesEnabled": false
}
```

## 0-3. 列を1つ作る

`+ 新しいステップ` → 同じく `SharePoint に HTTP 要求`

| 項目 | 値 |
|---|---|
| 方法 | `POST` |
| URI | `_api/web/lists/getbytitle('zz_test_build')/fields/createfieldasxml` |
| ヘッダー | 0-2と同じ2行 |

**本文**

```json
{
  "parameters": {
    "__metadata": { "type": "SP.XmlSchemaFieldCreationInformation" },
    "SchemaXml": "<Field Type='Text' DisplayName='起票ID' Name='TicketId' StaticName='TicketId' MaxLength='64' />",
    "Options": 12
  }
}
```

## 0-4. 実行して確かめる

1. 保存 → `テスト` → `手動` → `テスト` → `フローの実行`
2. 成功したら、SharePointで `zz_test_build` を開く
3. **リストの設定 → 列 → 「起票ID」をクリック**
4. **ブラウザのアドレスバーを見る**

**【撮影】** アドレスバー。末尾に `Field=TicketId` と出ていれば成功。

```
成功: ...FldEdit.aspx?List=...&Field=TicketId
失敗: ...&Field=_x8d77__x7968_ID
```

**ここが英字になっていることが、この方式を採る唯一かつ最大の理由。**

## 0-5. 判定

| 結果 | 次の行動 |
|---|---|
| 英字になった | 第1段階へ進む |
| 日本語がエンコードされた | **そこで止めて報告する。** 方式を見直す |
| リスト作成でエラー | エラー全文を撮影して報告 |

テストリストは、確認後に削除してよい。

# 第1段階：一括構築

## 1-1. フローを作る

```
Power Automate → 作成 → インスタント クラウド フロー
  名前: 管理_リストを構築する
  トリガー: 手動でフローをトリガーします
```

## 1-2. 定義を変数に入れる

`+ 新しいステップ` → `変数を初期化する`

| 項目 | 値 |
|---|---|
| 名前 | `lists` |
| 種類 | `アレイ` |
| 値 | `src/lists_definition.json` の **`"lists": [ ... ]` の中身（角括弧を含む）** を貼り付ける |

**貼り付ける範囲**

```
"lists": [          ← この行の [ から
  { ... },
  { ... }
]                   ← この ] まで
```

`$comment` や `libraries` は含めない。

## 1-3. リストごとに繰り返す

`+ 新しいステップ` → `それぞれに適用する`

| 項目 | 値 |
|---|---|
| 以前の手順から出力を選択 | 変数 `lists` |

**このアクションの名前を `ForEachList` に変える。**
（アクション右上の `…` → 名前の変更）

**後で式から参照するため、この名前が重要。**

## 1-4. リストを作る（ForEachList の中）

`アクションの追加` → `SharePoint に HTTP 要求`

| 項目 | 値 |
|---|---|
| 方法 | `POST` |
| URI | `_api/web/lists` |
| ヘッダー | 第0段階と同じ2行 |

**本文**（式を使う。`fx` から入力）

```
{
  "__metadata": { "type": "SP.List" },
  "BaseTemplate": @{items('ForEachList')?['template']},
  "Title": "@{items('ForEachList')?['title']}",
  "Description": "@{items('ForEachList')?['description']}",
  "ContentTypesEnabled": false
}
```

## 1-5. 列ごとに繰り返す（ForEachList の中）

`アクションの追加` → `それぞれに適用する`

| 項目 | 値 |
|---|---|
| 以前の手順から出力を選択 | 式で `items('ForEachList')?['fields']` |

**このアクションの名前を `ForEachField` に変える。**

## 1-6. 列を作る（ForEachField の中）

`アクションの追加` → `SharePoint に HTTP 要求`

| 項目 | 値 |
|---|---|
| 方法 | `POST` |
| URI | `_api/web/lists/getbytitle('@{items('ForEachList')?['title']}')/fields/createfieldasxml` |
| ヘッダー | 同じ2行 |

**本文**

```
{
  "parameters": {
    "__metadata": { "type": "SP.XmlSchemaFieldCreationInformation" },
    "SchemaXml": "@{items('ForEachField')?['xml']}",
    "Options": 12
  }
}
```

## 1-7. 同時実行を止める

**`ForEachList` と `ForEachField` の両方**で設定する。

```
アクション右上の … → 設定 → 同時実行制御 → オン → 並列処理の次数: 1
```

**列の作成順序を保つために必要。** 並列にすると順序が狂い、失敗も起きやすい。

## 1-8. 実行する

保存 → `テスト` → `手動` → 実行。

**【撮影】** 実行結果。失敗した場合は、失敗したアクションを開いて**エラー全文**を撮影。

## 1-9. 確認する

SharePointの `サイト コンテンツ` を開く。

```
手配起票 / 手配タスク / 手配明細 / 許可バージョン
```

の4つができていれば成功。

**【撮影】** サイトコンテンツの一覧

## よくある失敗

| 症状 | 原因と対処 |
|---|---|
| `The list already exists` | 既に同名のリストがある。消してから再実行 |
| `Value does not fall within the expected range` | SchemaXml の綴りか属性の誤り。どの列で止まったかを確認 |
| ヘッダーのエラー | `Accept` と `Content-Type` の2行が入っているか確認 |
| 列が一部しかできない | 同時実行が1になっていない（1-7） |

**途中で失敗した場合、できたリストを消してから作り直す**のが確実。
同じ列を二重に作ろうとするとエラーになる。

# 第2段階：仕上げ

## 2-1. 一意制約を付ける

**3箇所。それぞれ画面から設定する。**

| リスト | 列 |
|---|---|
| 手配起票 | 起票ID |
| 手配タスク | タスクID |
| 手配明細 | 明細ID |

```
リストの設定 → 対象の列をクリック
  → 「固有の値を適用する」を [はい]
  → 一番下の OK
  → 「この列にインデックスを付けますか？」→ OK
```

**このダイアログは正常な確認。** データが変わることはない。

## 2-2. Title列の表示名を変える

各リストの「タイトル」列を、実態に合った名前にする。

| リスト | 変更後 |
|---|---|
| 手配起票 | 起票の名前 |
| 手配タスク | タスク名 |
| 手配明細 | 品名 |
| 許可バージョン | 版数 |

```
リストの設定 → 「タイトル」をクリック → 列名を変更 → OK
```

**内部名は `Title` のまま変わらない。** 表示名だけが変わる。

## 2-3. 書式設定を貼る

`src/list_formatting.json` から該当の項目をコピーする。

**貼る前に `$use` `$desc` の行を消すこと。**

| 貼る先 | 使う項目 |
|---|---|
| 手配明細 の「数量」 | `明細_数量` |
| 手配タスク の「次の必要作業日」 | `タスク_次の必要作業日` |
| 手配タスク の「ステータス」 | `タスク_ステータス` |
| 手配起票 の「状態」 | `起票_状態` |
| 各「〜未定」列 | `共通_未定フラグ` |
| 「明細を見る」「タスクを見る」 | `共通_リンク` |
| 手配明細 の「手配完了」 | `明細_手配完了` |

```
列見出しをクリック → 列の設定 → この列の書式設定
  → 「詳細モード」に切り替えて貼り付け → 保存
```

**ビュー全体の書式**（`ビュー_タスク行`）は別の場所。

```
手配タスク のビュー → 現在のビューの書式設定 → 詳細モード
```

**【撮影】** 書式が効いた一覧。想定と違えば報告。

## 2-4. ビューを作る

`docs/リスト設計.md` §4 の表に従う。

**まず「手配タスク」の3つだけ**作れば十分。

| ビュー名 | 絞り込み | 並べ替え |
|---|---|---|
| 自分の担当 | 手配主担当 = [自分]、完了 = いいえ | 次の必要作業日 昇順 |
| 遅延 | 次の必要作業日 < [今日]、完了 = いいえ | 次の必要作業日 昇順 |
| 今週 | 次の必要作業日 <= [今日]+7、完了 = いいえ | 次の必要作業日 昇順 |

**既定のビューは「自分の担当」にする。**

## 2-5. 手配明細を隠す

```
リストの設定 → リスト名、説明、ナビゲーション
  → 「このリストをサイトのクイック起動に表示する」を [いいえ]
```

行数が膨らむため、直接開かせない。

## 2-6. 権限を設定する

**一度きりの作業。**

```
1. （サイトのURL）/_layouts/15/role.aspx を開く
2. 「投稿」を選び、内容をコピーして新しいレベルを作る
   名前: 投稿（削除なし）
   「アイテムの削除」のチェックを外す
3. 各リストの設定 →「このリストに対する権限」→ 継承を停止
4. メンバーに「投稿（削除なし）」を割り当てる
```

**サイト全体には適用しない。** ドキュメントライブラリでファイル名変更ができなくなる。

対象は3リスト（手配起票 / 手配タスク / 手配明細）。

## 2-7. 起票受付ライブラリを作る

```
サイト → + 新規 → ドキュメント ライブラリ
  名前: 起票受付
```

中にフォルダを3つ作る。

```
取込済 / 重複スキップ / エラー
```

**このライブラリのURLを控える。** 起票ツールのマスタ（`texts.libUrl`）に設定する。

## 2-8. 許可バージョンを登録する

配布する起票ツールの版数を1行追加する。

```
版数: 0.4.0
許可: はい
```

---

# 完了後

1. できあがったリストの画面を撮影して報告する
2. **起票受付ライブラリのURL**を控える
3. 未確認事項の結果を報告する（下記）

## 確認したい未確認事項

| # | 内容 | 見るところ |
|---|---|---|
| 1 | 内部名が英字になったか | 第0段階 0-4 |
| 2 | **ユーザー型の列で複数値が使えたか** | 手配副担当の列。設定に「複数選択を許可」があるか |
| 3 | 一意制約が一度で効いたか | 第2段階 2-1 で既に [はい] になっていたか |
| 4 | 書式設定が想定どおり見えるか | 第2段階 2-3 |

**2番が最重要。** 使えない場合、副担当の持ち方を変える必要がある。
